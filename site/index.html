dragology-swift

An unofficial Swift port of Dragology. Dragology and declarative dragging were created by Joshua Horowitz, Andrew Blinn, and Jeffrey Heer, who aren't involved in this port.

Tell SwiftUI what an element can turn into, and let the drag work itself out.

Good drag interactions usually take a lot of careful code: hit regions, offsets, snapping, animation. Declarative dragging is a different way to build them, from a UIST 2026 paper. You draw your state, and list the states each element can be dragged to. The library does the geometry.

This package brings that idea to iOS. It's a from-scratch Swift port of the web library, with every drag operator, drop-in views for common cases, and a gallery of more than thirty demos, most of them adapted from the original.

Permutation Lab, driven by real touches on an iPhone simulator.

Reorder anything

If you have an array, this is the whole integration. Your rows stay ordinary SwiftUI views: they size themselves, keep their state, and their controls keep working. 

DragList($tasks) { task in
    TaskRow(task: task)
}

DragBoard does the same for columns of cards. Both work inside a ScrollView, and with VoiceOver.

DragBoard($columns, cards: \.cards) { column in
    Text(column.title)
} card: { card in
    CardView(card: card)
}

Build your own

Lists are the easy case. The same engine handles any drag you can describe. This is all the code for a toggle, and nothing in it mentions touches, offsets, or animation. 

func toggle(_ context: SceneContext<ToggleState>) -> SceneNode<ToggleState> {
    SceneGroup {
        SceneRect(width: 120, height: 60, cornerRadius: 30)
            .fill(context.state.isOn ? SceneColor(hex: 0x22C55E) : SceneColor(hex: 0xD1D5DB))

        SceneCircle(radius: 26)
            .id("knob")
            .fill(.white)
            .transform(.translate(context.state.isOn ? 90 : 30, 30))
            .onDrag {
                context.drag.between([ToggleState(isOn: false), ToggleState(isOn: true)])
            }
    }
}

How it works

When a drag starts, the library calls your own render function on each state you listed. Where the element lands in each of those renders tells it where the targets are. Those few positions are enough to build the whole interaction.

Drags are also composable. Small behaviors combine into bigger ones, so drag.closest(spots).withFloating().whenFar(free) reads as what it does: float over the nearest spot, and move freely when far from all of them.

SwiftUI can't lay out a state that isn't on screen, so scenes are built from SceneNode, a plain-data tree that plays the part of SVG, and drawn by a SwiftUI Canvas. Real SwiftUI views go in with DragItem. The docs have the details.

Get started

Add the package to your app. It needs iOS 26 or macOS 26.

.package(url: "https://github.com/jeslyvarghese/dragology-swift", from: "0.3.0")

Then follow Getting Started. The operator guide has the full vocabulary, and DragList and DragBoard have their own pages.

Status

This is an early release. A few things to know before you depend on it:

  • It's been tested on the iOS simulator, but not yet on a physical iPhone.
  • DragList and DragBoard keep every row in memory. A few hundred rows stay smooth, and thousands won't.
  • To scroll in a parent ScrollView, use .dragActivation(.longPress()).
  • Drawn scene content isn't available to VoiceOver, though real views in a scene are.
  • The original's debug views aren't ported.

The docs list these, along with how it differs from the web version.
